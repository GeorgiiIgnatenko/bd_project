# Генератор данных · КТ-03

Генератор создаёт схему `dev` или `load`, применяет миграции 001–004 и заполняет
все 12 таблиц агрегатора новостей. Данные сохраняются после завершения.
Основная схема `public` не меняется. Пошаговый запуск и примеры чтения данных:
[главный README](../README.md).

## Запуск

Нужны Docker с Compose v2 и обычный `sh`. Для первоначального создания `.env`
используется Python 3; сам генератор выполняется в PostgreSQL без дополнительных библиотек.
Команды выполняются из корня репозитория.

```sh
sh start.sh

# Разработка: схема dev, 80 000 новостей.
sh generator/run.sh dev 42

# Нагрузка: схема load, 3 000 000 новостей.
sh generator/run.sh load 42
```

Обязательны ровно два аргумента: режим `dev|load` и seed — целое число
от 0 до 2147483647. Имя схемы совпадает с режимом и отдельно не задаётся.

При каждом запуске выбранная схема удаляется со всеми данными и создаётся заново.
Например, повторный `sh generator/run.sh dev 123` заменит только схему `dev`.
Схема `load` и данные `public` сохранятся. Удаление, создание таблиц, загрузка
и проверки выполняются одной транзакцией: при ошибке прежняя схема,
её строки и identity-счётчики восстанавливаются.

При старте PostgreSQL генератор автоматически не запускается. `run_demo.sql`
и `run_checks.sql` его также не вызывают. Для нагрузочного режима требуется
несколько гигабайт свободного места; точный размер зависит от хранения PostgreSQL.

## Проверка и работа с данными

Генератор проверяет критические инварианты перед `COMMIT`, обновляет статистику
планировщика через `ANALYZE` и выводит объёмы и распределения. Успех — сообщение
`Generation committed in schema ...` и код выхода 0. Повторная проверка готовых данных:

```sh
docker compose run --rm -T admin -v mode=dev -f /workspace/generator/verify.sql
```

Для нагрузочного набора замените `-v mode=dev` на `-v mode=load`.
Примеры запросов к таблицам приведены в главном README.

## Воспроизводимость

Версия генератора — 3. Выбор синтетического значения определяется комбинацией
`seed`, имени измерения и ID записи: первые 32 бита `md5(seed:dimension:id)`
приводятся к нужному диапазону. Имена измерений (`source`, `age`, `category` и другие)
разделяют выбор источника, даты, категории и пользовательских предпочтений.
MD5 здесь используется для распределения значений, а не для хранения паролей.

Нет зависимости от `random()`, `now()`, порядка выполнения запроса или текущих
identity-счётчиков. ID назначаются явно; после загрузки счётчики перезапускаются
со следующего свободного ID, поэтому обычные последующие вставки работают.
Контрольная дата фиксирована: **2026-10-01 00:00:00 UTC**. Все события находятся
до неё. Это исторический снимок; при анализе актуальности нужно сравнивать даты
с этой точкой, а не с текущим `now()`.

При одинаковых версии генератора, миграциях, режиме и seed получаются одинаковые
значения всех строк. Другой seed меняет источники,
даты, категории, длины текстов и пользовательские предпочтения, сохраняя объёмы.
Параметры сохраняются в комментарии схемы; их показывает `summary.sql`.

## Распределения

Проценты выбора ниже — целевые вероятности. Фактические доли немного меняются
с seed; точные количества пользователей, статусов источников и импортов фиксированы.

- **Источники новостей:** 70% выборов приходятся на источники 1–5,
  25% — на 6–30, 5% — на 31–100. Поэтому у популярных источников существенно
  больше публикаций, чем у редких.
- **Даты:** для источников 1–80 примерно 60% публикаций относятся к последним
  7 суткам перед контрольной датой, 25% — к промежутку 7–30 суток,
  15% — к промежутку 30–365 суток. Публикации источников 81–100 всегда старше
  30 суток. Поэтому для всего набора доля старых материалов немного выше 15%.
  Внутри выбранного диапазона меняются день и время суток.
- **Категории:** около 5% публикаций получают только «Без категории»;
  60% распределены между «Политикой», «Экономикой» и «Спортом»;
  33% — между девятью менее популярными обычными категориями.
  Оставшиеся 2% выборов предназначены для архивных категорий: если публикация
  моложе 30 суток, вместо архивной категории назначаются «Местные новости».
  Поэтому фактическая доля архивных категорий ниже 2%. Каждая новость получает
  ровно одну категорию; три архивные категории отключены, существующие связи сохранены.
- **Статусы источников:** 80 активных, 10 неактивных, 5 отключённых вручную,
  5 с ошибкой подключения. У неактивных последние три запуска завершились
  ошибкой подключения; у источников с ошибкой — последний один запуск.
- **Запуски сбора:** 36 500 завершённых окон — по одному на источник и день
  за 365 суток; окна без материалов допустимы. Ещё 35 запусков завершились
  ошибкой подключения, 8 находятся в состоянии «запущен» и не имеют результатов импорта.
- **Импорты:** на каждую сохранённую новость приходится один успех;
  дополнительно создаётся 8% от количества новостей результатов «дубликат»
  и 2% результатов «ошибка». Среди всех результатов это приблизительно
  90,91% успехов, 7,27% дубликатов и 1,82% ошибок. Ошибки отдельных материалов
  не меняют завершённый запуск на ошибку подключения.
- **Пользователи:** 99% имеют роль зарегистрированного пользователя, 1% —
  администратора. Гость представлен ролью, без зарегистрированной учётной записи.
  20% пользователей не имеют подписок и избранного; 60% имеют по одной подписке
  на категорию и источник и 2 избранные новости; 20% имеют 5 подписок на категории,
  4 на источники и 20 избранных новостей.
- **Популярность в избранном:** первые 1% ID новостей образуют популярный пул.
  Обычный пользователь сохраняет 1 материал из него и 1 из остальных;
  активный — 16 из него и 4 из остальных. В итоге около 73,08% всех добавлений
  приходятся на этот пул. ID популярного пула не означают самые свежие публикации.
- **Тексты:** непустые синтетические заголовки и тексты из 1–6 абзацев,
  содержащие тему, источник и номер публикации. Канонические URL и email уникальны.
  В `password_hash` используются три готовых корректных демонстрационных scrypt-хеша;
  генератор предназначен для запросов к БД, вход в приложение не моделируется.

## Целостность

Первичные и внешние ключи, `UNIQUE`, `NOT NULL` и `CHECK` включены при загрузке.
Данные создаются в порядке зависимостей. Дополнительно проверяется:

- у каждой новости есть категория и успешный импорт;
- служебная категория не смешивается с обычными;
- источник новости совпадает с источником успешного запуска;
- дата публикации не позже её импорта, записи журнала не раньше запуска;
- у дубликатов и ошибок `news_id` равен `NULL`, новая новость не создаётся;
- у незавершённых и провалившихся запусков нет результатов импорта;
- ошибки материалов и подключения имеют записи журнала;
- новые подписки направлены на активные обычные категории и активные источники;
- текущие статусы источников согласованы с завершающей серией ошибок;
- количество строк соответствует выбранному режиму.

Это согласованный синтетический снимок. Генератор не выполняет HTTP-запросы
и не реализует сборщик, авторизацию или пользовательский интерфейс.

## Файлы

| Файл | Назначение |
| --- | --- |
| `run.sh` | Запуск через уже существующий сервис PostgreSQL |
| `generate.sql` | Параметры, пересоздание схемы, транзакция и identity-счётчики |

| `summary.sql` | Количества, статусы, популярность и даты |
