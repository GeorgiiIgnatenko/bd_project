# Документная модель MongoDB

Документ фиксирует, какие данные переходят в MongoDB, кому они принадлежат и как устроены коллекции.

## 1. Принцип разделения

PostgreSQL используется для данных со строгими связями, транзакциями и требованиями к целостности. MongoDB — для данных с изменчивой структурой, которые удобно хранить и читать целиком одним запросом.

## 2. Задачи для MongoDB

| № | Задача | Проблема в PostgreSQL | Преимущество MongoDB |
|---|---|---|---|
| T1 | Отображение карточки новости | Данные новости, источника и категорий находятся в разных таблицах, нужны JOIN.| Все данные хранятся в одном документе, читается одним запросом.|
| T2 | Хранение ответов источников | Разные источники возвращают данные разной структуры, сложно заранее создать общую схему. | Можно хранить данные любой структуры без изменения схемы. |
| T3 | Хранение событий по новостям| Быстрорастущая таблица мешает аналитике и политикам RLS. | События хранятся отдельно и быстро добавляются. |
| T4 | 	Пользовательские подборки | Для хранения подборок и их элементов нужны две таблицы и JOIN. | Подборка вместе со всеми элементами хранится в одном документе. |

В PostgreSQL остаётся: учётные записи и роли, справочники (`category`, `news_source`),
подписки и избранное, запуски сбора и результаты импорта,
аналитические запросы Q1-Q8, журнал аудита, журнал миграций.

## 3. Модель владения данными

| Данные | Где хранятся | Источник истины |
|---|---|---|
| Пользователи, роли | PostgreSQL | PostgreSQL |
| Категории, источники | PostgreSQL | PostgreSQL |
| Новости и их категории | PostgreSQL | PostgreSQL |
| Подписки, избранное | PostgreSQL | PostgreSQL |
| Запуски сбора, результаты импорта, ошибки | PostgreSQL | PostgreSQL |
| Журнал аудита, журнал миграций | PostgreSQL | PostgreSQL |
| Копия новости для быстрого чтения (`articles`) | MongoDB | PostgreSQL |
| Сырые ответы источников (`import_payloads`) | MongoDB | MongoDB |
| События по новостям (`article_events`) | MongoDB | MongoDB |
| Подборки пользователей (`reading_lists`) | MongoDB | MongoDB |

### Правила согласованности

1. Каждые данные изменяются только в своей основной базе. Двойная запись не используется.
2. `articles` — копия новостей из PostgreSQL. Вручную её не правим, а при расхождении верим PostgreSQL.
3. Транзакция импорта остаётся в PostgreSQL.
   Публикация в MongoDB выполняется после `COMMIT`.
4. При удалении новости в PostgreSQL в `article` устанавливается `deletedAt`. Связанные подборки и события обрабатывает приложение.
5. Подписки и избранное остаются в PostgreSQL, поскольку используют RLS. Доступ к подборкам в MongoDB проверяет приложение.

## 4. Коллекции

Четыре коллекции.

### 4.1. `articles` - карточка новости (T1), связь 1:1

Источник истины: PostgreSQL.

```json
{
  "_id": 1000,
  "canonicalUrl": "https://sportexpress.example/news/transfer-window",
  "title": "Итоги зимнего трансферного окна",
  "content": "Клубы завершили сделки…",
  "publishedAt": "2026-10-01T10:00:00Z",
  "source": { "id": 2, "name": "Sport Express API" },
  "categories": [ { "id": 2, "name": "Спорт" } ],
  "meta": { "author": "…" },
  "deletedAt": null
}
```
`_id` совпадает с `id` новости в PostgreSQL. Источник и категории лежат внутри документа.

### 4.2. `article_events`  - события новости (T3), связь 1:N

Поток событий. Одна новость, много событий. Каждое событие ссылается на новость через `articleId`.

```json
{
  "articleId": 1000,
  "userId": 1,
  "type": "view",
  "at": "2026-10-02T08:15:00Z"
}
```

### 4.3. `import_payloads` - сырые ответы источников (T2), связь 1:N

Один запуск сбора, много сырых элементов. Ссылка на запуск: `scrapeRunId`.

```json
{
  "scrapeRunId": 7,
  "sourceId": 2,
  "format": "json_api",
  "receivedAt": "2026-10-01T10:00:02Z",
  "raw": { "…": "ответ источника" }
}
```

### 4.4. `reading_lists` - подборки пользователя (T4), связь M:N

Пользователь составляет много подборок, новость входит во многие подборки.
Новости лежат внутри подборки списком со ссылкой `articleId`.

```json
{
  "userId": 1,
  "name": "Почитать позже",
  "items": [
    { "articleId": 1000, "addedAt": "2026-10-02T09:00:00Z", "note": "про трансферы" }
  ]
}
```

В одной подборке не более 200 новостей.

### 4.5. Связи между сущностями

| Связь | Тип | Реализация |
|---|---|---|
| `news` (PostgreSQL) → `articles` | 1:1, проекция | `articles._id = news.id` |
| `articles` → `article_events` | 1:N | ссылка `article_events.articleId` |
| `scrape_run` (PostgreSQL) → `import_payloads` | 1:N | ссылка `import_payloads.scrapeRunId` |
| `app_user` (PostgreSQL) ↔ `articles` | M:N | `reading_lists.userId` и встроенные `items[].articleId` |

Между PostgreSQL и MongoDB нет внешних ключей, поэтому ссылки проверяет приложение.
